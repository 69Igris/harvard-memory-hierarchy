Introduce the team and the one-line goal: compare a Harvard memory organisation (separate instruction and data memories) with a shared one, then extend it to a realistic cache hierarchy.
The problem

A CPU needs memory twice per instruction

Every instruction must be fetched. Loads and stores must also read or write data.

FETCH

Happens every cycle: read the next instruction at address PC.

DATA

Only lw / sw, about 20–47 % of instructions in our programs.

QUESTION

Can both use the same memory in the same cycle? That choice is the whole project.

The scrolling stream is a real instruction mix. The orange ones (lw, sw) need a second memory access in the same cycle as the fetch.
Two organisations

One road, or two roads?

Left: one port, so the fetch and the data access take turns and a load/store stalls the CPU one cycle. Right: two ports, both happen at once.

Phase II · the real world

But real memory is slow

The brief's optional part: one shared lower-level memory that holds code and data and takes LAT cycles to answer.

At LAT = 8 with no cache, CPI jumps from 1 to about 12.

Splitting the ports without caches: 12.28 → 12.01. Only about 2 % better, because both roads still end at the same slow memory.

Key insight: two roads only help if each road has something private and fast on it. That is a cache.

This is why Phase II exists. Without caches, the Harvard advantage almost disappears once memory is slow and shared.

Proposed design · modharvard_top.v

Harvard at the top, shared memory below

This is what real CPUs do. The core sees Harvard (two ports, both hit in one cycle). Main memory is Von Neumann (one copy of code and data). The arbiter only sees traffic when a cache misses.
Timing · LAT = 4, 4-word line

Anatomy of a miss, cycle by cycle

Miss penalty = LAT + words per line = 4 + 4 = 8 cycles. A store costs 1 cycle thanks to the write buffer.

Press to play. lw misses at cycle 0; the arbiter grants at once; memory waits LAT cycles, then streams 4 words. At cycle 8 the lw hits and retires. The sw at cycle 9 goes into the write buffer and the core moves on while memory writes in the background.

Conclusion

What we learned

  • Harvard removes the structural hazard: CPI 1.00 vs 1 + fmem (up to 1.47× in Phase I).
  • Split paths alone don't help with slow shared memory: only about 2 %.
  • Modified Harvard (split L1 over shared memory) is the winner: 1.40× over unified, 6.1× over no cache, at lower hardware cost.
  • Everything is self-checked: 266/266 runs with exact model agreement.

Limits & next steps: single-cycle core, direct-mapped caches, 1-entry write buffer, no FPGA timing. Next: a pipeline, set-associative caches, a deeper write buffer, an FPGA run.

End on the one sentence: real CPUs are Harvard at L1 and Von Neumann below, and our numbers show why.
